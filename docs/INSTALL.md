# StepBar 安装与使用指南

公开下载仍为 **v0.1.8**，检索优化尚未发布。源码自建与下载包的候选数量／模型上下文行为不同，参见 [三层检索](RETRIEVAL.md)。不要将源码测试结果当作已安装应用验收。

## 下载与系统要求

需要 macOS 13+、Apple Silicon（M 系列芯片）及 Google Chrome。目前只发布 arm64 包，Intel 用户需自行构建，尚无对应安装包。

- [下载最新版 ZIP 与查看版本说明](https://github.com/liuedcson/hackathon-StepBar/releases/latest)
- [扩展源码](../browser-extension/)

以上 GitHub 资源公开，无需登录或 Token。解压后把 StepBar.app 移入 `/Applications` 或 `~/Applications`，双击启动；应用常驻屏幕顶部菜单栏，不显示 Dock 主窗口。

## 首次启动被 Apple 拦截

当前包仅使用本机签名，没有 Developer ID 签名与 Apple 公证。确认来自可信 Release 后：

1. 尝试打开一次 StepBar。
2. 前往 **系统设置 → 隐私与安全性**。
3. 在页面下方「安全性」找到 StepBar 的拦截提示，点击 **仍要打开**。
4. 输入密码或 Touch ID，再确认打开。

没出现按钮时重新尝试启动后返回设置。组织管理设备可能不允许放行，需管理员处理。明确检测到恶意软件、提示“会损坏电脑”或“已损坏”时不要盲目绕过，先核对下载包。不推荐关闭系统安全检查或去除整个目录的隔离属性。

不需要辅助功能或完全磁盘访问权限。语音启用后首次录音才申请麦克风权限；拒绝后可在「隐私与安全性 → 麦克风」调整。正式发布解决办法是 Developer ID 签名、Hardened Runtime、Apple 公证并附加公证票据，本版尚未完成。

## 配置模型

菜单栏 →「设置」→「模型配置」，填写后点「保存设置」，再点「测试已保存的 AI 配置」。

- 官方 Step Plan：地址固定，默认后台 step-5-preview、前台 step-3.7-flash，共用你的 Step Plan Key。
- 自定义：后台、前台分别填 Base URL、Model ID 和 Key。搜索与语音单独配置；默认关闭，不借用 Step Plan。Bing 网页入口仅供点击，不能给模型提供搜索结果。
- API Key 默认仅在已有授权时静默载入；无授权留空，不弹钥匙串密码窗口。未编辑密码框时保存不会删除已有 Key；主动编辑并清空后保存才删除。测试分别请求后台、前台，`max_tokens=1`，只验证连通性，不验证业务生成、搜索或语音。安装包不包含密钥，也不会自动加载源码旁的 config.local.json。不配置 AI 仍可先测试本地检索。

## 安装 Chrome 扩展

扩展源代码在 Git 仓库 `browser-extension/`。本机配对文件 `pairing.json` 自动生成，不提交到 Git、不共享、不手动输入。

### 安装包用户：自动准备与配对

1. 保持 StepBar 正在运行，点击菜单栏 →「设置」→「Chrome 扩展」→「安装 Chrome 扩展」。
2. Chrome 地址栏输入 `chrome://extensions`，开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择应用准备的 `browser-extension` 文件夹。
4. 若找不到，在选择窗口按 ⌘⇧G，输入 `~/Downloads/StepBar-browser-extension`。
5. 不要选择应用包、压缩文件或单个 JS；不要在加载后移动／删除扩展目录。

v0.1.1 点击安装时准备 **`~/Downloads/StepBar-browser-extension`**，弹出 Finder 并选中它。在 Chrome 选择该文件夹即可；再次点击可刷新文件，之后重新加载扩展。下载目录并不是临时安装文件：Chrome 持续依赖它，请不要清理或移动。v0.1.0 仍使用 Application Support 路径，升级后移除旧扩展并加载新目录。

### 源码用户：自动连接

1. 克隆仓库或下载源码 ZIP 并解压。
2. 在 Chrome 开发者模式加载源码中的 `browser-extension/`。
3. 开发运行的 StepBar 会向可定位的源码扩展目录写入自动配对文件；若未连接，改用「安装 Chrome 扩展」导出的目录。
4. StepBar 设置 →「Chrome 扩展」→「测试连接」。无需查看或填写配对信息，不共享本机 `pairing.json`。

### 验证连接与排查

- 加载扩展后点击 StepBar 的「测试连接」，收到扩展真实确认才显示连接成功，不切换或关闭页面。
- 如果失败，确认本机应用运行、扩展连接启用且未暂停，重新点击安装扩展，并在 Chrome 中重新加载。
- 更新后点击扩展「重新加载」，自动读取本机配对信息。
- 干净重装时先移除旧扩展再安装新扩展，避免重复连接。不会修改 Chrome 原有历史与其他扩展。
- 不装扩展：历史搜索仍可用，但标签页信息、切换／关闭和正文读取能力不可用。

## 第一次使用与验收

1. 按 ⌘M 唤起，输入一个 Chrome 历史页面标题，确认本机结果出现。快捷键冲突时从菜单栏唤起，或改用设置中的其他快捷键。
2. 打开两个公开网页，再搜索已打开网页的标题，按 ↩，检查切回原标签页。
3. AI 配置测试通过后，输入公开项目查询，观察本机候选与后续 Step 推荐；网络故障时本机结果应仍可用。
4. v0.1.5 在配置完成后立即分批准备，并按 15 分钟或新增 10 条增量分析。查看设置中的准备进度与「记忆」，不保证每批请求固定耗时。
5. 重复选择同一输入对应的页面，观察已学习选择是否优先出现。不是每次都需要调用模型。
6. 按需配置语音，先唤起 StepBar，再在面板内长按 ⌥M 说话，松开进入文本搜索。不默认采集、不后台录音；完整现场麦克风与按键验收仍需实际测试。

按 ↑ ↓ 选择，↩ 打开，⌘1–9 直达，Tab 再生成，⌘⌫ 关闭所选标签页，Esc 先清空再关闭。直接唤起不输入时，会结合剪贴板与最近页面给建议。

源码优化版：空输入仅本地建议，不调用模型；用户主动输入／粘贴／语音转写才作为 query。明确 `github apple/swift` 可本地直达；普通查找无答案时按搜索设置兜底，回忆查询不生成搜索冒充历史。联网等待最多 1.2 秒不等于总响应时间；晚结果下次复用，缓存 5 分钟过期。

## 更新与版本边界

设置 →「版本与更新」，默认启动时及每 6 小时自动检查公开 Releases，无需 Token，可关闭。下载与安装需用户确认，校验 SHA-256、版本、Bundle ID 和相同签名身份；网络故障或匿名请求限流时手动下载。更新后重载 Chrome 扩展。

建议把应用放在 `/Applications` 或 `~/Applications` 再打开。v0.1.6 起，如果应用被 macOS 隔离运行，更新时会弹窗让你选择真正的 `StepBar.app`；仅接受身份和签名一致、父目录可写且非符号链接的目标。安装工具等待当前进程退出后再替换；退出前失败明确弹窗，退出后的安装失败尝试恢复旧应用并写入本机 `update.log`。不会去除隔离属性，也不要求关闭 Gatekeeper。选择器和完整实机升级仍需现场验收。

v0.1.5 及更早版本若因隔离运行或确认窗口问题无法升级，请先手动安装一次 v0.1.6，获得新的目标选择与错误提示流程。

v0.1.1 纳入中文语音无空格站内搜索修复。网址可能失效，部分网站需要登录；真实麦克风按键录音与用户现场跨版本升级仍需验收，未来跨应用 MCP 能力尚未实现。

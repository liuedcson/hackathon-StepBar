# StepBar 技术实现

版本口径：公开下载仍为 **v0.1.8**。本文检索实现对应工作区未发布源码，不代表已安装应用；详细契约与测试边界见 [三层检索](RETRIEVAL.md)。

StepBar 的长期方向是轻量级办公 Toolbar，连接上下文与常用工作路径。当前实现运行在 macOS 上。**本文先描述已实现的 Chrome 验证版，最后单列未来跨应用连接设计；规划不代表已交付或已支持其他操作系统。**

当前是原生 Swift（AppKit + SwiftUI）菜单栏应用，没有第三方依赖。数据来自 Chrome 历史数据库和一个本机配对的 Chrome 扩展。默认模型调用走 StepFun Step Plan；设置中也支持后台记忆、前台检索独立配置 OpenAI 兼容服务。

## 模型配置与路由

`Settings` 保存模式及两组 Base URL / Model ID，不保存 Key。凭据存于被忽略的本机配置文件或钥匙串；自定义后台和前台使用独立钥匙串账户。`RuntimeChecks.summaryConfiguration` 与 `quickConfiguration` 是统一路由入口，App、诊断和 CLI 共用。

官方模式固定 `https://api.stepfun.com/step_plan/v1`，默认后台 step-5-preview（high）、前台 step-3.7-flash（low）。自定义模式分别使用用户配置，不发送 `reasoning_effort`；JSON 模式可选。保存时校验两个端点和 Model ID，清空当前请求上下文与联网缓存，新设置立即生效。

官方搜索和语音使用 `stepPlanConfiguration`。自定义模式完全独立：搜索默认关闭，可配置搜索引擎入口或 JSON API；API 请求 POST `{query,n}`，响应 `{results:[{title,url,snippet,time?}]}`，密钥独立。搜索引擎入口仅供用户点击，不伪称为模型的实时信息。语音默认关闭，启用后使用独立的 OpenAI 兼容 multipart 音频转写接口、Model ID 和 Key；16 kHz PCM 包装为 WAV，响应 `{text}`。未启用或未配置完整时不触发录音或麦克风权限。所有自定义请求禁止重定向，避免转发凭据。设置中的 AI 连接测试分别测试后台和前台，仅发送合成文本。

```
                    ┌──────────── 唤起时（前台，越快越好） ────────────┐
 ⌘M / 面板内长按⌥M 说话 ──► 主动输入／粘贴／语音 query
                     │
                     ├─ L1 原始标题／URL 匹配 ─────────────────────┐
                     ├─ L2 结构化本地索引（后台任务）────────────────┤──► 先显示本地结果
                     │                                                 │
                     └─ 停止输入 150 ms ─► 联网软等待 1.2 s，与 L2 并行
                                               └─► 去重／RRF Top5 + 模板 ─► L3 step-3.7-flash
                                                                       └──► 「✦ Step 推荐 / 生成」置顶

                    ┌──────────── 平时（后台，越细越好） ─────────────┐
 Chrome 历史 / 扩展上报的标签页与正文 ─► 清洗 ─► step-5-preview（reasoning high）
                                               ├─ 页面理解：实体、别名、用途、关键词、问法 → L2
                                               └─ 网址模式：{value} 模板 → 独立直达／L3
 用户选择 / 站内搜索 / 复制 ID 后访问的网址 ─► 本地学习 → 相关项加权／独立直达
 当前页／剪贴板 ─► 本地建议与学习；不作为前台模型上下文
```

## 1. 数据来源

| 来源 | 实现 | 说明 |
|---|---|---|
| Chrome 历史 | 复制各 Profile 的 `History` SQLite 到临时目录后只读查询（数据库被 Chrome 锁定） | 近 90 天；去跟踪参数合并、登录/OAuth/跳转页和搜索结果页不进候选 |
| 标签页 | 扩展 `browser-extension/` 通过 `127.0.0.1:17373` 上报 | 每个请求带配对码；支持切换、关闭；确认后才算成功 |
| 页面正文 | 扩展在页面停留数秒后取 `meta description` + 主体 `innerText` 前 3000 字 | 无痕窗口、密码页不取；脱敏后存本机 |
| 剪贴板 | 唤起时和每秒 tick 读取 | 疑似密钥整段丢弃，个人信息替换，最长 500 字 |
| 语音 | 唤起后长按 ⌥M 录 16 kHz PCM，SSE 流式发给 `stepaudio-2.5-asr` | 仅显式长按时录音，不后台采集 |

扩展把 `bundle` 固定为 `com.google.Chrome`。当前验证版只支持 Chrome：不截图、不读屏幕、不读其他应用和文件。这是阶段性实现边界，而非 StepBar 的长期产品边界。

## 2. 唤起流程（`Launcher.swift`、`Layers.swift`）

`Layers` 是一个纯值类型，App 和命令行诊断（`--search-check`）共用，保证线上和测试走同一套逻辑。

### L1 历史匹配

`Layers.history(text)` 返回两组：

- **direct（独立直达，≤3）**：完整网址、学到的查询入口、点名站点的站内搜索及明确 `github owner/repo`。不占 L1／模型候选；回忆任务不生成这些动作。
- **matches**：`Ranker.rank(rawOnly: true)` 仅匹配标签页和历史的原始标题／URL；明确回忆时间先过滤，允许只有时间线索的召回。选择历史只给已经相关的项加权，不注入无关页面。UI 展示数量与模型融合前召回数量分开。

### L2 语义匹配

`LocalIndex` 在后台任务构建并缓存，仅检索 Step 5 已整理的 entity、terms＋aliases、asks、purpose（权重 3／2.5／1.5／1）。混合脚本分词、倒排索引、IDF 与覆盖率门槛缩小匹配范围；明确回忆任务再过滤时间窗、按清洗置信度加权。不用原始标题或正文冒充结构化兜底，无 notes 时 L1／联网仍可用。历史／标签页／notes 变化使索引失效，revision 防旧任务覆盖；点击次数与选择日志不重建索引。不是 embedding 检索，也不在线调用额外模型。

### L3 ✦ Step

`queryChanged` 每次按键先同步 `compose()`，再调用 `scheduleAI(after:)`：

1. 睡眠 `Store.debounce`（150 ms）；新输入取消旧排队／前台请求，`searchGeneration` 和 requestID 防旧结果回写。已经发送的请求仍可能产生用量，不能保证连续输入只产生一次服务端请求。
2. 已经很确定时跳过 L3：同一输入选过同一页面两次以上，或直接输入了网址。
3. **联网搜索**（`WebSearch.swift`）：只发送 query；官方 `POST /step_plan/v1/search`，自定义使用独立 JSON API。`SoftDeadline` 从搜索启动起软等 1.2 秒，与 L2 并行；底层请求仍受 URLSession 超时限制，软截止不等待慢任务退出。返回结果脱敏、清洗并摘取报道中的原始链接。
4. 必须等 L2 完成，`Fusion.merge` 将 L1、L2、及时联网结果整体保守去重并排序：精确命中优先，再按 RRF（L1=1，L2／WEB=0.9，分母 20+rank），最多 5 个，不凑满／不设来源配额。仅发送 `query/task/candidates/templates`，模板最多 12；无 current／clipboard，也不把剪贴板伪装 query。
5. 模型返回 mode／picks／actions／fallback，逐项解码、校验后展示。前台上限 600 tokens、独立请求超时 15 秒（resource 30 秒）。失败／双空明确反馈；只按隐私与搜索配置提供确定性兜底，回忆只挑本地历史／标签页。

同 query／设置共享在途搜索；晚非空结果仅缓存，不修改当次候选或追加模型调用。缓存 5 分钟、最多 100 项，淘汰最旧项；暂停／配置变化清缓存并取消搜索。空输入仅本地建议，不自动调模型；收起面板取消旧前台与排队请求，手动 Tab 替代排队生成。

`Fusion.key` 仅规整 host、默认端口和已知 tracking；保留协议、www、路径大小写／尾斜杠、语义参数顺序与 fragment。跨源同 URL 保留本地身份／tab 引用、补结构字段和摘要，不重复累加访问数；`Clean.merge` 同源，旧记忆 ID 不破坏性迁移。

**联网门控**（`WebSearch.allows`）：明确过去访问线索由 `Inference.recalling` 统一判定；普通问句、“的”和今天／昨天发布的新闻不自动算回忆。网址、秘密、个人信息、长数字／混合 ID、hex/UUID 不联网；`gpt-5`、`2026` 等短词可联网。

**程序对模型输出的校验**：

- 动作只能是 http/https，拒绝 localhost、内网地址、`.local` 和带凭据的链接；
- 裸模型 URL 拒绝；动作只能引用同一模板快照，或提供对应候选 id 与逐字相同 URL；
- 模板只代入真正来自 query 的值，且形状匹配；搜索不得新增 query 中没有的实体，拒绝路径穿越；
- 与已有候选重复的动作被丢弃。
- 校验 mode／fallback 枚举，pick／generate 分支隔离，none 不接受夹带结果；兼容省略 mode 的旧格式。有效 picks／actions 校验后各最多 2，置信度须有限且 ≥0.5。客户端搜索兜底不受模型声称已找到答案影响。

### 打开

标签页已打开时，通过扩展切换到原标签页；否则在 Chrome 打开网址。每次选择写入 `choices`（全局频次）和 `queryChoices`（输入 → 页面），并记入 `searchLog` 用于 `--eval-search`。

## 3. 后台理解（`Background.swift`、`Study.swift`）

后台任务全部使用 `step-5-preview`、`reasoning_effort: high`（环境变量 `STEPBAR_STUDY_EFFORT` 可改），请求超时 300 秒。后台不赶时间，更细致的结果更划算。

| 任务 | 输入 | 输出 | 用在哪 |
|---|---|---|---|
| 页面理解 `Understand` | 每批最多 10 页：标题、网址、正文前 300 字；新页面、更新及旧 schema 分批升级 | schema=2：kind、entity、purpose、terms、aliases、asks、confidence | L2 索引；L3 候选描述 |
| 网址模式 `PatternMiner` | 每次 3 个网站，每站 ≤25 个真实地址 | 含一个 `{value}` 的模板、中文名、参数说明 | L1 查询入口；L3 生成网址的依据 |

模型输出都要经过程序校验：网址模式必须至少匹配 2 个输入地址，且除 `{value}` 之外与真实地址逐字一致；页面理解逐项容错，只接受输入序号且去重、再次脱敏、校验长度／枚举。schema=1 旧 notes 继续可用，逐批升级，不先清空记忆。完整字段上限见 [三层检索](RETRIEVAL.md)。

**调度**：`Store.tick` 每秒运行一次，`backgroundJobs` 优先做网址模式，没有待办时做页面理解。

- 首次有可用配置立即分批准备，此后 `PreparationSchedule` 每 15 分钟或新增待分析满 10 条触发并排空待办；不要求接电或空闲。
- 每批最多 10 页／3 个网站，模型输出上限 4096 tokens；失败指数退避（1 分钟起，最长 1 小时）。不再使用小时额度阻断历史准备。
- 唤起面板不取消后台；暂停、修改配置会取消。`usage.json` 仅持久化响应用量计数，不存提示词、密钥或网址。
- Chrome Ready 以经过鉴权的报告或命令轮询心跳为准，超过 60 秒过期，监听端口成功不等于扩展已连接。

## 4. 本地学习（`Store.swift`）

| 记忆 | 来源 | 作用 |
|---|---|---|
| `queryChoices` | 输入 → 打开的页面 | 已相关结果小幅加权；相关原始页面选择 ≥2 次可跳过 L3 |
| `choices` | 全局打开频次 | 排序加权 |
| `recipes` · 站内搜索 | 当前标签页网址匹配搜索模板（`?q=` 等） | 「站名 + 词」直达站内搜索 |
| `recipes` · 剪贴板入口 | 复制 ID 后 120 秒内访问的网址里出现了这个 ID | 复制新 ID 后直达对应页面 |
| `notes` / `patterns` / `studied` | 后台模型 | L2 与网址模式 |
| `remembered` | 选中结果的快照 | 历史过期后仍可找回 |

学习到的入口 180 天未使用才淘汰；`choices` ≤1000、`queryChoices` ≤800、`recipes` ≤300。保存时先做值快照，再在后台串行队列写盘。

## 5. 隐私与安全

- 数据都在 `~/Library/Application Support/StepBar/`（`memory.json`、页面正文、设置）。Key 只存在于 git 忽略的 `config.local.json`（权限 600）或钥匙串。
- 发给模型和搜索之前统一脱敏（`Privacy`）：手机号、座机、邮箱、证件号替换为占位符；疑似密钥整段丢弃；带 `token`、`code`、`session` 等参数的网址整条丢弃（脱敏后的地址也打不开，不如不用）。
- 联网结果、页面正文都按不可信数据处理，提示词要求忽略其中的指令；程序只信任校验过的网址。
- 桥接只监听回环地址，默认端口被占用时自动尝试 17374–17393；以实际绑定成功为准，通过本机配对文件同步端口，扩展每次同步前读取。不终止占用端口的程序。使用每次安装自动管理的本机配对凭据，不在界面展示或要求用户输入。设置中的连接测试发送无副作用命令，收到扩展鉴权确认后才显示成功，端口监听或旧心跳不算测试通过。
- 设置中可以排除域名（同时删除相关记忆），也可以关闭 AI、后台理解或联网搜索，或暂停使用。

## 6. 模型分工与耗时边界

| 用途 | 模型 | 当前口径 |
|---|---|---|
| L3 挑选与生成 | `step-3.7-flash`（reasoning low） | 本轮未测真实服务；600 输出上限的实际质量待验收 |
| 联网搜索 | Step Plan `/search` 或独立自定义 API | 软等 1.2 s，不是端到端 SLA；晚结果仅缓存 |
| 后台页面理解、网址模式 | `step-5-preview`（reasoning high） | 分批异步，不阻塞前台；仍消耗 Token／电量 |
| 语音转写 | `stepaudio-2.5-asr`（SSE） | 三段合成语音真实转写及源码搜索测试通过；麦克风/按键录音待现场验收，见发布说明 |

旧阶段的局部测速不作为本轮 Top5／新提示词的质量或延迟保证。`--model-bench` 可在用户明确授权使用配置后测端到端表现；本轮没有读取真实凭据／历史做基准。

## 8. 测试

`./scripts/test.sh` 编译并运行核心与桥接测试（不依赖 Xcode 的 XCTest），覆盖匹配、学习、后台理解、网址模式、分层、联网搜索、网络传输，以及桥接鉴权、上下文、命令路由与确认。网络请求用 `URLProtocol` 模拟，不调用真实接口；另有隔离安装脚本测试。`STEPBAR_TEST_UI=1` 增加临时 AppKit 确认窗口测试，不代替真实应用完整升级验收。

真实效果用命令行诊断验证：`--search-check` 逐层打印候选、联网结果和模型输出；`--model-bench` 测端到端耗时；`--understand` 跑一轮后台任务并校验输出。

本轮核心与隔离 Store 测试还覆盖保守去重、RRF Top5、L1 原始数据隔离、旧 schema、坏条目容错、模板证据、回忆路由、历史时间窗、软截止／晚缓存／在途共享／过期、取消与索引失效。40 条基础及 20 条困难合成查询通过；12 个无线索同名入口仅留 5、裁掉 7，未解决歧义。真实 Recall@5、生成正确率、跨版本数据与端到端耗时仍待验收。

## 9. 未来设计：办公工具连接与工作路径（未实现）

### 连接方式

目标是让用户授权的应用通过 MCP 或适配器提供上下文与能力，由 StepBar 统一组织。不是所有应用都天然支持 MCP：是否采用应用自带服务、本机适配器、事件订阅或受控轮询，需要逐个验证。MCP 是连接协议，不会自动授予系统权限或替我们完成长期记忆。

当前 `BrowserBridge` 是专用回环 HTTP 协议；尚无跨应用 MCP 客户端、通用连接器或事件总线。后续可以把它作为一个浏览器连接器保留或适配，但不宣称协议兼容已完成。

### 拟议的数据闭环

```
用户授权的应用 / MCP / 适配器
           ↓ 有来源、时间与权限范围的上下文
事件与工作对象 → 最小化 / 脱敏 / 权限检查
           ↓
本机工作路径记忆：对象关联、常用入口、已确认的动作顺序
           ↓
唤起时：当前上下文 + 路径候选 + 用户输入 → 下一步建议及理由
           ↓ 用户选择 / 纠正 / 确认
受控打开入口或调用工具 → 执行回执 → 更新记忆
```

路径不只保存网址，还需关联应用、工作对象、参数、动作能力、来源、时间与置信度。先后发生不代表因果关系；应结合重复行为和用户确认学习组合，允许纠正和过期，不能只记录应用切换就推断完整意图。

### 建议与执行分离

例如授权的团队消息事件关联到一个服务对象，StepBar 可以提出指标页、日志查询和排查文档的组合；此例仅说明未来意图，不代表当前能读取消息或调用这些工具。模型只提出候选，程序验证目标、权限及参数，用户确认后才执行。工具回执决定是否成功，不能以“已发送请求”替代完成。

### 生态级连接的安全门槛

- 每个连接器独立授权，只共享用户允许的字段；权限可撤销，不自动读取全部消息、文件或窗口。
- 应用内容与 MCP 工具结果均是不可信数据，不能借其中的指令扩大权限或窃取其他应用信息。
- 本机记忆可查看、纠正、删除，定义保留期限；跨应用共享不等于把全部上下文发送给云端模型。
- 读取上下文、打开入口和修改数据分开授权；发送、写入、删除与组合动作要明确确认及结果记录。
- 先验证一个跨应用只读场景，再逐步扩展；当前版本的安全校验不会因愿景而放宽。

# StepBar 产品设计

## 要解决的问题

用户真正的工作跨越多个应用：从消息到资料，从问题到工具，从一次操作到下一次操作。信息在各处，工作路径却要靠用户自己记住和串联。即使找到了一个页面，仍要判断下一步去哪。

**StepBar 的核心目标是让整个 Mac 在办公场景下越用越好用：连接上下文，学习常用工作路径及工具组合，预测用户下一步的意图，并在唤起时提供可选择的入口。** 它是 macOS 工作伙伴，不是以 Chrome 为最终边界的搜索工具。

当前先从浏览器里的高频问题验证：昨天看过的文档、某个项目的仓库、常用的查询工具、某个 ID 对应的详情页。现有方式各有短板：

- **地址栏**只按标题和网址前缀匹配，换个说法就找不到（想找「阶跃 API 鉴权」，页面标题却叫「基本概念」）；
- **书签**需要提前整理，而且很快就会过时；
- **搜索引擎**不知道你看过什么，新出的项目也常被转载文章淹没；
- **对话式 AI** 要多轮来回，最后还得自己复制链接去打开。

当前版本的阶段目标是：**一个快捷键加几个词，直接到达目标网页**。长期目标是：**一个快捷键，让下一步工作所需的入口已经在眼前**。

## 长期定位与当前取舍

长期希望通过 MCP 或应用适配器连接用户授权的 macOS 应用，共享必要上下文与能力。应用之间有共同的工作对象和关联路径，StepBar 负责整理这些关系，而不是成为另一个孤立的聊天窗口。

以下是 **v0.1.0 的范围**，不是永久的产品边界：

| 做 | 不做 |
|---|---|
| Chrome 标签页与历史、页面用途、网址结构 | 其他浏览器、桌面应用、本地文件、窗口管理 |
| 打开、切换、生成可直接打开的网址 | 对话问答、长文本回答 |
| 剪贴板作为上下文（复制的 ID、时间戳） | 截图、读取屏幕内容 |
| 联网搜索输入的词，补齐模型不知道的新信息 | 把历史、剪贴板、页面内容发去搜索 |
| 后台慢慢理解，前台尽快响应 | 让用户在面板前等后台任务 |

受时间与部分技术条件限制，先落地 Chrome：它承载了大量办公入口，便于验证理解、记忆、路径学习和推荐是否真正减少操作。当前浏览器扩展使用本机 HTTP 桥接，并非 MCP；不把未来生态连接宣传成已实现。

## 未来体验：工作路径，而不是孤立结果

以下为规划示例，不涉及任何真实组织、消息或系统：

1. 用户在团队消息应用中看到一条服务告警；授权连接器共享相关事件及工作对象。
2. StepBar 根据已确认的使用习惯，关联该对象的指标入口、日志查询和排查文档，形成“了解问题 → 查看指标 → 查日志”的工作路径。
3. 用户按 ⌘M，看到“继续排查”的建议组合及推荐原因，选择后进入对应工具。
4. 本次选择或纠正成为下一次推荐的依据；用户可以修改、删除或暂停学习。

同一理念也适用于“会议 → 关联资料 → 待办”“需求 → 项目 → 文档”等办公路径。重点不是接入应用数量，而是少一次寻找、少一次切换、少一次重新解释上下文。

## 当前版本的核心体验

### 1. 先给结果，再给更好的结果

面板一打开就有内容，每次按键本机结果都会实时刷新（约 1 ms）。停止输入 150 ms 后，Step 的结果到达并置顶，带 ✦ 和置信度。网络慢或失败时，本机结果照常可用。

结果分组固定：剪贴板 / ✦ Step 推荐 / ✦ Step 生成 / 直达 / 历史匹配 / 语义匹配 / 网页 / 标签页 / 最近。用户能看出每一项是怎么来的。

### 2. 三层理解

| 层 | 回答的问题 | 例子 |
|---|---|---|
| 历史匹配 | 字面上是哪个页面？以前选过什么？ | `deeps` → 上次选过的 DeepSeek 搜索页 |
| 语义匹配 | 哪个页面是干这个用的？ | `阶跃 api 是啥` → 「基本概念」文档 |
| ✦ Step | 用户到底想做什么？目标地址是什么？ | `kimicode github` → 联网结果中的官方仓库 |

第三层能看到前两层的结果，所以它主要做判断，而不是从零开始搜索。

### 3. 联网获取最新信息

模型的知识有截止时间。用户问的常常是刚发布的项目或产品，比如 `kimicode github`。第三层之前，StepBar 会用输入的词联网搜索一次，把结果和摘要作为上下文交给模型。报道里引用的官方地址会被单独摘出来，模型因此能直接打开官方仓库，而不是一篇转载文章。

为了隐私，回忆类输入、网址和含 ID 的输入不联网，也只发送输入的词本身。

### 4. 越用越好用

- 每次选择都会被记住，同一输入的结果下次会置顶；足够确定后不再调用模型，结果瞬间出现；
- 搜过的网站自动学会站内搜索；
- 复制 ID 后打开的详情页会被学成「查询入口」，下次复制新 ID，可以直接打开从没访问过的页面；
- 空闲时后台模型阅读访问过的页面，写下用途、关键词和常见问法，并归纳每个网站的网址结构。

用户可以在「Step 的理解与记忆」窗口里查看这些学习结果，也可以逐条删除。

### 5. 少打字

- 唤起后在面板内长按 ⌥M 说话，松开即搜索，不会后台录音；
- 不输入直接唤起时，根据剪贴板给出建议（复制了网址就打开，复制了时间戳就转换），并列出最近的页面。

## 模型选择

| 场景 | 要求 | 选择 |
|---|---|---|
| 前台第三层 | 快，稳定，判断准确 | `step-3.7-flash`，低推理强度 |
| 后台理解 | 细致；不赶时间 | `step-5-preview`，高推理强度，空闲且接电源时才运行 |
| 语音 | 短句实时转写 | `stepaudio-2.5-asr` |

全部通过 Step Plan 调用，一个 Key 即可。

设置支持官方 Step Plan 和自定义 OpenAI 兼容服务。自定义模式的后台记忆、前台检索、搜索 API、语音转写分别配置，不调用 Step Plan；搜索和语音默认关闭。搜索也可选 Bing 等网页入口，但不会作为模型上下文；无法配置语音服务时保持关闭，不录音、不申请权限。

## 信任与隐私

- 记忆只存在本机，可以查看、删除、排除域名、暂停；
- 发出的数据最小化：前台最多 14 个候选的标题、地址和摘要，联网只发送输入的词；
- 统一脱敏，疑似密钥的内容整段丢弃；
- 模型生成的地址要经过程序校验，不打开内网地址、不打开带凭据的链接，也不编造私有域名；
- 只打开页面，不替用户点击、提交或执行任何操作。

## 后续方向

以下为规划，未作为当前能力交付，也未承诺时间表：

1. **把浏览器闭环做可靠**：完善语音、来源可信度、排序评估、安装与升级；查询入口从单参数扩展到多参数。
2. **接入授权应用**：以 MCP 和适配器连接不同工具，定义明确的上下文来源、权限和可用动作；不默认获得全系统访问权。
3. **整理工作路径与组合**：从用户确认的行为中关联“事件 → 工作对象 → 常用工具 → 下一步”，支持查看、编辑、删除和纠正。
4. **预测下一步**：唤起时结合近期事件、当前任务和路径记忆推荐入口；展示依据，不确定时询问，不把一次偶然切换当成长期习惯。
5. **受控协作**：先只读上下文与打开入口，再逐步支持经确认的跨应用动作；写入、发送、删除等操作需单独授权与确认。

衡量成功不仅看搜索命中率，更看完成任务减少了多少寻找与切换、下一步建议的采纳与纠正情况，以及错误建议和隐私成本。用户信任优先于“自动化程度”。

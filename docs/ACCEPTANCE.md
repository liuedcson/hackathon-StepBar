# StepBar 产品验收

发布前同时覆盖逻辑、真实窗口交互和隔离安装链路；编译成功不能代替功能验收。

## 自动检查

```sh
STEPBAR_TEST_UI=1 ./scripts/test.sh
```

- 核心检索、学习、页面理解、网址模式、输入隐私门控。
- 官方／自定义请求路由、max_tokens=1 连通性、截断与错误响应。
- 匿名更新请求、默认自动检查与偏好保存。
- Chrome 桥接鉴权、报告、命令及确认。
- 真实 AppKit 更新确认窗口出现、取消不安装、确认只触发一次安装。测试使用临时窗口，不运行已安装应用。

## 安装与更新链路

- 发布 ZIP 的版本、架构、SHA-256、Bundle ID、签名及隐私扫描。
- 与上一版相同的签名要求；不覆盖已有标签与资源。
- 在隔离目录中验证下载、解压、签名检查、退出等待、替换、失败恢复与重启调用。
- 实际设置页的按钮必须显示确认，下载与校验阶段必须反馈状态；错误不得静默消失。
- 更新不得清除记忆、模型配置、配对或钥匙串。

## 设置与权限

- 菜单栏只有设置、暂停／恢复、退出；快捷键注册不得改名设置项。
- 首次安装无 Key 时界面可用；默认读取钥匙串不得弹授权窗口。
- 已有访问授权时静默读取；无授权时留空，未编辑密码框保存不得删原 Key。
- 官方／自定义模式相互独立；语音未配置不录音、不申请权限。
- 暂停后不学习、不启动延迟联网任务；旧任务不得回写当前查询。
- 扩展安装入口在设置中，导出目录易定位；配对更新后可重新连接。
- 卸载工具须核对应用身份并显式确认，保留 Chrome 用户资料和源码配置。

## 需真实设备验收

以下不能由单元测试冒充已完成：Apple 首次放行、升级后的钥匙串 ACL、麦克风权限与按键录音、Chrome 实际加载和目标网站登录、真实运行应用的完整跨版本更新。发布说明应区分已自动验证与待现场验证。

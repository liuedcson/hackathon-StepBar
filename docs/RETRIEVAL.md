# 三层检索优化（未发布）

下载包仍为 v0.1.8；本文描述工作区实现，不表示已替换本机应用或完成真实服务验收。

## 数据流

```text
用户主动输入／粘贴／语音转写的 query
  ├─ L1：Chrome 原始标题和 URL 文本匹配
  ├─ L2：Step 5 已整理的结构化字段 → 本地倒排索引
  └─ 可用联网结果（受隐私、回忆查询和配置门控）
        → 保守 URL 去重 → 精确命中优先 + RRF → 最多 5 个候选
        → Step 3.7 挑选／模板生成 → 本机校验 → 用户选择打开
```

确定性查询入口、站内搜索和命令保留在独立 UI 通道，不冒称 L1 文本命中、不占模型候选槽。历史选择仅对已有相关结果加权，不注入无关页面。匹配到同查询至少两次选择过的原始页面、或输入完整 URL 时保留免模型快路径。

## L1 和 L2

- `Layers.history` 使用 `Ranker.rawOnly`：只匹配原始标题／URL，不使用别名、摘要或 Step 5 关键词。短 ASCII 词用边界检查避免 RL 命中 URL。
- `LocalIndex` 使用 Step 5 的 entity、terms + aliases、asks、purpose，权重分别为 3、2.5、1.5、1。原始标题和未整理正文不作为 L2 兜底；无 notes 时 L1 和联网仍可工作。
- Unicode 兼容归一化与小写；中文和拉丁字母按脚本分段，中文长段切二元组，拉丁词不切英文二元组。
- 倒排索引缩小匹配集合，IDF 降低高频词权重，覆盖率至少 0.5，或精确实体命中；显式时间范围过滤，置信度降低弱整理数据的分数。
- 索引仅在历史／标签页／notes 变化时失效，点击次数／选择日志不触发重建；生产查询在后台任务构建新索引。缓存写回校验 revision，旧任务不能覆盖新缓存。

## 去重与融合

统一函数为 `Fusion.merge`，App 与 CLI 共用。每路最多召回 30 个本地结果；联网提供全部已清洗结果（包括报道中摘出的原始链接），不在融合前再取前 5。

去重键 `Fusion.key`：域名小写、去默认端口、删除现有白名单中的跟踪参数。保留协议、www、大小写敏感路径、尾斜杠、查询参数顺序、有意义的查询参数及 fragment/SPA 路由。不用标题、host+path 或模型主体键合并页面。历史加载 `Clean.merge` 也使用这一保守键。

同 URL 跨层命中保留本地身份和标签页引用，补结构化信息／联网摘要，来源并集；不把跨层重复当成新访问量。已有记忆 ID 不进行破坏性迁移。

排名融合为 `Σ weight/(20+rank)`，L1 权重 1，L2 和 WEB 各 0.9；完整标题／URL 精确命中优先，历史选择加权限制在很小范围。同分按规范 URL 固定排序。不强制来源配额、不按 host 限额、不凑满 5。这些权重是实现起点，不是已证实最优参数。

## Step 5 清洗与结构

完整运行系统提示词：`Sources/StepBar/Background.swift` 的 `Understand.prompt`。

输入为页面数组 `{i,title,url,text?}`，标题最多 80 字，正文摘录最多 300 字，真实 URL 不由模型改写。发送前脱敏；原有排除网站／敏感 URL 过滤、批大小 10、4096 输出上限、high effort、截断减半重试一次保持不变。

输出：

```json
{"schema":2,"items":[{"i":0,"kind":"doc","entity":"SwiftUI","purpose":"Apple 的声明式界面开发框架介绍","terms":["SwiftUI","声明式界面"],"aliases":[],"asks":["苹果写界面的框架"],"confidence":0.9}]}
```

客户端逐项容错解码、校验输入序号并拒绝重复序号，清理空白、长度、数量、泛词、重复词并再次脱敏。保留标题中的有价值实体，不为字段凑数量。kind 只接受既定枚举，置信度限制 0–1，完全无内容的记录不标记已学习。purpose 最多 40 字、entity 40、terms 8×20、aliases 4×20、asks 3×24。

落盘 `PageNote` 兼容旧字段缺省值；schema=1 的旧 notes 保留可检索，后台按既有批次逐步整理为 schema=2，不先清空旧记忆。模型不产出去重键、官方域名或一票否决负词。

## 3.7 输入输出和生成

完整运行系统提示词：`Sources/StepBar/Assistant.swift` 的 `Assistant.actionPrompt`。前台输出上限 600，官方仍 low effort；连接测试仍仅 max_tokens=1。

```json
{"query":"苹果写界面的文档","task":"find","candidates":[{"id":"c0","sources":"语义匹配+联网结果","kind":"doc","title":"SwiftUI","url":"https://developer.apple.com/xcode/swiftui/","entity":"SwiftUI","purpose":"声明式界面开发框架","terms":["SwiftUI"],"asks":["苹果写界面的框架"],"snippet":"简短摘录"}],"templates":[]}
```

只有 `query/task/candidates/templates`，不含 current、clipboard，也不把剪贴板隐式当 query。候选最多 5，terms 与 asks 分开，摘录最多 160 字。相关模板最多 12，参数值最多 3；不发送全部历史或全部学习数据。

```json
{"intent":"查找文档","mode":"pick","picks":[{"id":"c0","confidence":0.9}],"actions":[],"fallback":"none"}
```

模板动作 `{title,template_id,value}`；已知地址动作 `{title,candidate_id,url}`。模型最多 2 个 picks、2 个 actions；picks 必须有效 c0–c4、有限置信度至少 0.5。

本机根据同一模板快照生成 URL。ID／路径值必须来自已提供的真实 query 值且符合形状；搜索值中的每个词必须能在 query 找到，拒绝新增实体、路径穿越或隐私受限搜索。裸模型 URL 没有依据一律拒绝，已知地址要求对应候选逐字相同，并过滤与候选重复的动作。保留 HTTP/HTTPS、敏感 URL 和公网主机校验。

普通查询双空时由客户端提供确定性搜索入口：点名站点优先；官方模式使用既有搜索入口，自定义模式不会偷偷改用 Google。关闭搜索、回忆、秘密、个人信息或长 ID 等受限查询不提供公共搜索兜底。回忆只 pick 本地来源，不伪造历史答案。独立本地剪贴板建议仍可使用，但不自动触发模型。

## 验收

### 联网软截止

`SoftDeadline.wait` 在搜索启动后最多等 1.2 秒，计时与 L2 并行；L2 仍必须完成才能融合。及时返回的联网结果参与本次 Top 5，超时则仅使用本地候选开始一次 3.7 调用。1.2 秒是当前策略参数，不是整条流水线的响应保证。

搜索本身继续受既有 URLSession 超时限制。晚到非空结果只写缓存，不更改本次候选、不主动追加模型调用；下次同查询复用。相同查询与设置的在途搜索共享任务，避免重复请求。设置改变会清理旧缓存，旧设置或暂停期间的结果不能写回；失败／空结果不长期缓存。CLI 搜索检查与模型测速也使用同一软截止。

软截止单测覆盖及时完成、慢任务不阻塞、晚结果可复用及等待取消不取消搜索。Store 隔离测试覆盖缓存复用、在途任务复用、候选不被晚结果修改及配置／暂停门控；不调用真实搜索或读取真实凭据。

`Tests/StepBarTests/RetrievalTests.swift` 覆盖跨层重复、同名不同 ID／路径／参数／协议／fragment 保全、Top 5 上限和稳定排序、L1 数据隔离、混合脚本分词、覆盖率、旧 notes 解码与逐项容错、模板生成／路径生成、猜测 URL 拒绝、重复生成拒绝、回忆不生成、payload 无上下文字段。

额外使用 40 个独立可识别的合成查询检查 Top1 和 Recall@5；2k／20k 合成结构化页面输出索引构建与查询 p50／p95。Store 隔离测试覆盖缓存随 notes 变化刷新及空输入不生成。

新增 20 条困难合成查询：口语用途、中英混写、短 ASCII 词边界和同名页面的编号定位；同时比较裁剪前召回、Recall@5 与 Top1。测试发现“订单7”的数字段被丢弃，已保留单个数字用于匹配。另有纯联网新项目／重复报道和无答案用例。

无额外线索的 12 个同名工作台仍只能保留 5 个，测试明确记录 7 个裁剪损失，不宣称消除了歧义，也不以来源配额掩盖。用户可继续手动选择更多本地结果；真实查询的召回悬崖仍待现场或脱敏数据评估。

### 高 ROI 收尾

- 回忆路由统一使用明确过去访问线索：普通问句、语气词、“的”、今天／昨天发布新闻不再自动等于回忆。WebSearch、payload、模板、生成校验及 picks 共用判定。真正回忆不生成直达动作或公共搜索，picks 只允许本地历史／标签页。
- L1 对明确的历史时间查询先过滤时间窗再匹配原始标题／URL，支持“昨天看的那篇”只按时间召回，即使 Step 5 尚不可用。L2 只对回忆任务使用时间过滤，候选额外携带访问日期供 3.7 判断。
- 明确输入 `github owner/repo` 可以使用已知 GitHub 路由立即直达，不依赖后台先学模板；模型使用同样的本地模板和 query 原值。拒绝路径穿越，不从普通名称猜组织／仓库名。
- 输出逐条容错解码，校验 mode/fallback 枚举；mode=none 不接受夹带动作，pick/generate 分支隔离，兼容省略 mode 的旧格式。有效结果校验后才限制最多 2 条，坏条目不能抢占名额。
- 双空和失败显示真实状态并使用已有配置允许的搜索兜底；不以模型生成的 intent 声称已找到答案。前台独立请求超时 15 秒（resource 30 秒），不缩短后台分析请求。
- 新 query／收起面板／暂停／改配置会取消旧前台模型和排队请求，requestID 防止旧任务清理新任务状态；手动 Tab 生成替代排队自动调用。已发出的请求可能已产生服务端用量，取消不能保证免费。
- 搜索缓存 5 分钟过期、最多 100 条，满时淘汰最旧项而不是全清；改配置／暂停取消在途搜索并清缓存。晚结果仍仅缓存，不重复调用模型。
- 仅 notes 变化失效 L2 缓存，点击次数／选择日志变化不会重建索引。命令保留独立 UI 通道，不占模型候选。

停止继续增加算法复杂度：拼写纠错、向量／额外重排模型、广泛工具模板、模型结果缓存和自动网页探活均暂缓。下一阶段应先现场验收和测真实端到端质量；没有数据时继续调权重或扩充“猜测直达”收益不明确且增加风险。

这些是合成单测和本地观察，不代表真实历史 Recall@5、线上生成正确率、真实网络延迟或 UI 首屏速度。真实服务、现场输入、跨版本数据和完整端到端准确率仍须验收；未读取真实凭据或历史来做基准，不新增 HEAD 探活或真实查询日志。
